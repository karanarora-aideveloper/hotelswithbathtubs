Hotels With Bathtubs — Fix Plan

For: Product Manager · hotelswithbathtubs.com · Prepared 23 Oct 2026 · Priority: H high, M medium, L low · Tick the box when the test passes

How to read this plan. Each task has what is wrong and what we change (two lines), then a simple test anyone can do without code. Work is in phase order. Phase 1 comes first because broken booking links cost revenue and trust.
  • Nothing is written to the live database until the product owner approves a preview of the changes.
  • If a hotel link cannot be verified, we remove it. We never replace it with a search page.

Phase 1 — Booking links do first · revenue and trust

IDPTask: what we fix, and how to test
1.1HCheck links on the real sites (sample run) We test a sample of Booking.com and Trip.com links in a real browser to measure how many are dead or wrong. Results are saved to a report only; nothing on the site changes.
Test: open the report and spot check 10 rows by hand; the result in the report should match what you see.
1.2HBooking.com buttons that open a search page Some hotel links (e.g. Nouvata, Noumea) open a city list instead of the hotel. We find the correct hotel page by name and city, or remove the button.
Test: pick 10 random cities, click each Booking.com button; every one must show the same hotel name.
1.3HTrip.com links show "0 properties found" 2,930 of 3,120 Trip.com links are keyword searches that Trip ignores, so visitors land on an empty page. We swap them for the hotel's real Trip.com page, or remove them.
Test: click 10 Trip.com buttons across countries; each must open the named hotel, never an empty list.
1.4MAgoda links go through a search step 988 Agoda links use a search address instead of the hotel page, and 28 are missing our affiliate ID. We use direct hotel pages and add the ID everywhere.
Test: click 10 Agoda buttons; the hotel page opens directly and the address contains our ID (cid=1972736).
1.5MMakeMyTrip: almost no hotel pages for India Only 24 of 1,548 India hotels have a MakeMyTrip hotel page, so most India clicks earn nothing there. We look up the real hotel pages and leave the rest empty.
Test: open 10 India hotels; each MakeMyTrip button opens that hotel. Count of hotels with a MakeMyTrip page goes up from 24.
1.6MTwo hotels share one Booking.com link 13 Booking.com links are used by two different hotels, so one of them points to the wrong place. We fix or remove the wrong one.
Test: the report lists the 13 pairs; open each pair and confirm every hotel now opens its own page.
1.7MOld link field mixes everything 3,177 hotels keep links in an old catch-all field. We move each link into its own platform field so the right button and badge show.
Test: a hotel with a MakeMyTrip page shows "Verified on MakeMyTrip"; a hotel without one does not.
1.8HSearch pages must never be a booking button The site currently allows some Trip.com search links to appear as buttons. We block any search-type link from being shown as a booking button.
Test: browse 20 hotels; every visible booking button opens a hotel page, none opens a list.
1.9MRedirect button blocks some partners The "/out" redirect only allows some partner sites, so Trip.com, Expedia, Hotels.com, Airbnb and Vrbo clicks would fail if routed through it. We allow the partners we actually use.
Test: click one button for each partner; each opens the partner page, not an error.
1.10MAutomatic link check on every release There is no automatic safeguard, so broken links can ship again. We add a quick sample check on every build and a full check weekly.
Test: deliberately add one bad link in a test copy; the build must fail and name the hotel.
1.11LOld addresses after link repair If a hotel's page address changes during repair, old addresses must forward to the new one. We add forwarding rules.
Test: open an old hotel address from the report; it forwards to the new page.

Phase 2 — Trust and rich-result data how Google reads each hotel page

IDPTask: what we fix, and how to test
2.1HWrong prices in search-result data (done, needs check) Prices like "$1,234.50" were read as 123450. Price is now parsed correctly, and left out when it is a range or missing.
Test: test 5 hotel pages in Google's Rich Results Test; price matches the page and no errors show.
2.2HStar ratings and FAQ markup removed (done, needs check) Star ratings came from booking partners, which Google does not allow us to mark up. Template FAQ markup is removed; visible text stays.
Test: Rich Results Test shows no rating or FAQ data; the page still shows its ratings and FAQ to visitors.
2.3HHotel pages read like copies of each other About 4,400 hotel pages use the same sentences with names swapped, which Google treats as thin. We add facts that differ per hotel: tub type, room, area, who it suits.
Test: read 5 pages in one city; each has at least 3 facts not found on the others.
2.4M"Verified" claims need proof Pages say "triple-checked" without showing how. We add a short "how we verify" note and a last-checked date, or soften the wording.
Test: every hotel page shows a verification date and links to the method.
2.5LPrices inside search descriptions go stale The text shown in Google includes "Starting at $X", which changes. We remove the price from that text.
Test: view page source of 5 hotels; the description has no price.
2.6HInternal audit files are public 13 MB of internal hotel audit files could be downloaded from the live site. They are now removed from the deployed site and blocked in robots (done).
Test: after deploy, www.hotelswithbathtubs.com/audits/hotels_master_audit_latest.csv shows "not found".

Phase 3 — Search indexing so Google finds the right pages

IDPTask: what we fix, and how to test
3.1MDefault "canonical" points to the homepage A new page that forgets its own setting would tell Google "I am the homepage". We remove the default so each page must state its own.
Test: view source on 5 different page types; each canonical is its own address.
3.2MSitemap "last updated" dates are unreliable Many dates are typed by hand or change on every build, so Google learns to ignore them. We use real content dates only.
Test: open sitemap.xml twice after two builds with no content change; dates do not change.
3.3M"Index only if 2+ hotels" rule is in three places If the copies disagree, the sitemap lists pages marked "do not index". We keep the rule in one place.
Test: pick a city with 1 hotel; it is absent from the sitemap and marked noindex.
3.4LMistyped hotel addresses redirect blindly The fallback can permanently redirect a typo to a guessed page that does not exist. It will show "not found" unless the target is confirmed.
Test: open /india/goa/not-a-real-hotel; you see the 404 page, not a redirect loop.
3.5HReview real search data We have not looked at Google Search Console numbers. We pull indexed vs submitted pages, errors and top searches to find real problems.
Test: a one-page summary of indexed count, top 10 errors and top 20 queries is delivered.

Phase 4 — Site speed a Google ranking factor

IDPTask: what we fix, and how to test
4.1MFive font families on every page Every visit downloads five fonts, slowing the first view. We reduce to one or two.
Test: Lighthouse mobile score on home, a city and a hotel page is higher than before.
4.2MThree tracking tools load at once Google Analytics, Mixpanel and PostHog all load immediately. We load them after the page is usable and review whether we need all three.
Test: events still appear in each tool; mobile loading time improves.
4.3LEvery build needs the database The site layout reads the database during build just to get the analytics ID, so a database outage can break releases. We read it from settings instead.
Test: a build succeeds with the database turned off.
4.4LScraping tools shipped as site dependencies Browser-automation and scraper packages sit in the production list, bloating installs and widening security risk. We move them to developer-only.
Test: the site builds and deploys as before; the production install is smaller.

Phase 5 — Code quality and security

IDPTask: what we fix, and how to test
5.1M194 code-quality errors The code checker reports 194 errors (mostly loose typing) that the build ignores. We fix them and make the build fail on new ones.
Test: the lint command ends with 0 errors.
5.2HAdmin area protection unconfirmed The admin pages and tools exist in the code, and we have not confirmed they require a login. We verify login and make sure they never go live in the public site.
Test: /admin on the live site shows "not found"; locally it asks for a login.
5.3LMissing browser security headers The site does not send standard protection headers. We add them.
Test: securityheaders.com gives the site a grade of A or better.
5.4LCheck against the Next.js 16 guide The project uses a newer Next.js than most documentation covers. We read the local guide and re-check our Next-specific code against it.
Test: a short list of any deprecated or changed features found, each fixed or noted.

Phase 6 — Repository cleanup

IDPTask: what we fix, and how to test
6.1LOld files clutter the project Old static pages, scraper scripts, test logs and a PDF sit in the repository. We archive or delete them.
Test: the repository is smaller; the site still builds and looks the same.
6.2LGenerated files saved as code changes Sitemaps and data files are regenerated and committed, creating noise. We generate them during the build only.
Test: a fresh build leaves no uncommitted changes.
6.3LSetup notes and sample settings missing New developers have no example settings file or current instructions. We add both.
Test: someone new follows the README and runs the site in under 30 minutes.

Phase 7 — Verify and release

IDPTask: what we fix, and how to test
7.1HFull build and live spot check We confirm type and lint checks pass, the Cloudflare build succeeds, and a sample of live pages is correct.
Test: check 10 live pages for title, hotel name, working booking buttons and no console errors.
7.2MTell Google and re-measure We resubmit the sitemap in Search Console, re-inspect key pages, and re-run the link audit to fill in the before/after table.
Test: the sitemap shows "Success" in Search Console; the measures table is complete.
